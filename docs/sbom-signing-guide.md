# SBOM and Image Signing Guide

> Addresses issue #1489: container scanning, SBOM generation and signed images.

## Overview

Every released image for `apps/api-py` must carry:

1. A CycloneDX SBOM (generated by Trivy in CI).
2. A cosign signature proving the image came from a CI run on the canonical
   repository.

## Generating an SBOM Locally

```bash
# Install Trivy
brew install aquasecurity/trivy/trivy  # macOS

# Build the image
docker build -t mixmatch-api-py:local apps/api-py/

# Generate a CycloneDX SBOM
trivy image --format cyclonedx --output sbom.json mixmatch-api-py:local

# Generate a Syft SBOM (alternative)
synk sbom --format cyclonedx-json mixmatch-api-py:local > syft-sbom.json
```

## Signing Images with cosign (keyless)

```bash
# Install cosign
brew install cosign

# Sign (keyless – uses OIDC identity from the GitHub Actions runner)
cosign sign --yes mixmatch-api-py@<digest>

# Verify
cosign verify \
  --certificate-identity-regexp 'https://github.com/MixMatch-Inc/MixMatch-Onchain' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  mixmatch-api-py@<digest>
```

## Pinning Critical Dependencies

The following packages in `apps/api-py/pyproject.toml` must use pinned
lower bounds (not open `>=` ranges) in production:

| Package | Minimum | Reason |
|---|---|---|
| `cryptography` | `>=43.0.0` | Active CVE fixes |
| `pyjwt` | `>=2.8.0` | Algorithm confusion fix |
| `stellar-sdk` | `>=10.0.0` | Breaking SEP changes |
| `hvac` | `>=2.0.0` | Vault API v2 required |
